### 权限模型（三层）

| 层 | 表 | 作用 |
| --- | --- | --- |
| 接口级 | — | `/api/admin/**` 限 ADMIN；配置类写接口 ADMIN/ANALYST |
| 资源级 | `rbi_permission` | 报表/目录对角色是否可见、是否可编辑；有记录即受限，无记录为公开 |
| 行级 | `rbi_data_scope` | 按列值白名单限制可见行，注入 `${row_filter}`，缺占位符 403 |
| 列级 | `rbi_column_policy` | 隐藏列或对列值掩码（手机/身份证/邮箱/姓名/全掩码），隐藏列禁止用于聚合 |

## 二、明确不具备的能力（上线前需评估）

1. **数据权限的表达力仍有限**
   行级支持"列 = 若干值"与白名单语法表达式（比较、AND/OR、IN、括号、白名单函数），加 `${deptTree}` 覆盖部门树继承；但**仍不支持子查询、窗口函数、按时间窗口的滚动权限**，且不支持"某人额外放行"的用户级例外（只有角色级）。

2. **身份与合规能力仍不足**
   有 OIDC、LDAP 绑定、MFA、会话吊销、密码过期；但**没有 SSO 多租户隔离、没有 MFA 恢复码、没有 SCIM 自动同步、没有 LDAP 组到角色的自动映射**，审计也只有导出没有"留存期策略 + 防篡改"。

3. **报表版式深度不及成熟商业产品**
   没有真正的分组分页（按分组重新起页）、页眉页脚只支持居中文案、没有条件样式、打印模板与图表联动钻取。

4. **调度是"应用内调度"**
   有重试、退避、告警、多节点租约，但任务执行占应用线程；没有独立调度节点、没有任务执行历史表（仅 last_run_time + last_error + 审计日志）、没有失败告警的升级策略。

5. **API 数据集较简陋**
   只支持 GET/POST + 简单 `${param}` 替换 + 点号路径取值；没有分页拉取、鉴权令牌轮转、重试、响应字段类型声明。

6. **无多租户、无数据导出水印**

## 三、上线前置条件（Checklist）

### 必须

- [ ] 设置 `RBI_JWT_SECRET`（≥32 字节随机串）；
- [ ] 设置 `RBI_ALLOWED_ORIGINS` 为实际前端域名；
- [ ] 设置 `RBI_RESET_URL` 为前端可达地址，否则找回邮件里的链接不可用；
- [ ] 首次初始化后设置 `SPRING_SQL_INIT_MODE=never`；
- [ ] MySQL 独立账号，元数据库与业务库分离；
- [ ] 反代终结 TLS，后端仅监听内网；
- [ ] 修改 `admin` 初始口令、清理演示账号、为用户补 `email`；
- [ ] 邮件相关：`RBI_MAIL_HOST/PORT/USER/PWD`，以及告警接收人 `RBI_ALERT_TO`；
- [ ] 若启用 API 数据集：`RBI_API_DATASET_HOSTS` 只放业务允许的主机（默认全禁）；
- [ ] 备份 `rbi_platform` 元数据库。

### 建议

- [ ] 接入集中日志与 `/api/health` 告警；
- [ ] Nginx 对 `/api/auth/login`、`/api/auth/forgot` 做限流；
- [ ] 定期跑三套冒烟脚本回归；
- [ ] 关闭 `rbi.security.reset-debug`（默认已关闭）。

## 五、结论

**可以用于**：内网演示、POC、报表能力评估、二次开发底座；补齐 TLS/域名/邮箱/白名单后可用于中小规模内部生产（含 SSO、MFA、会话吊销、密码过期、三层数据权限、导出水印、独立调度）。

**仍不建议直接**：公网多租户交付、强合规场景（缺少 SCIM/组映射、审计留存策略与防篡改、LDAP 仅做过失败分支验证）。
