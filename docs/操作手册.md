## 1. 系统概览

### 1.1 是什么

一套可私有化部署的报表与自助分析平台：数据接入 → 数据集建模 → 复杂报表设计 → 参数查询 → 可视化大屏 → 数据填报 → 自助分析 → 指标治理 → 权限调度 → 运维监控。前端静态资源内置在 Jar 中，一个进程对外提供 UI 与 API。

### 1.2 架构

```
浏览器 (Vue 3 SPA, 内置在 Jar 的 /static 下)
        │  HTTPS（由 Nginx 终结）
        ▼
┌──────────────────────────────┐
│ 应用进程 (Spring Boot 2.7)    │  ← 可多实例（会话在库、令牌版本在库）
│  ├ /api/**  JWT 拦截器 + RBAC │
│  ├ 报表引擎（单元格扩展/公式） │
│  ├ 数据集执行（SQL / API）     │
│  ├ 导出（Excel/PDF/CSV+水印）  │
│  └ 审计切面（写操作落库）      │
└───────────┬──────────────────┘
            │ JDBC
            ▼
   MySQL 8：rbi_platform（元数据） + rbi_testdb（业务库，可替换为你的库）

┌──────────────────────────────┐
│ 独立 worker 进程              │  ← 同一 Jar，profile=worker，不启 Web
│  每 30s 扫描 cron，租约防重    │
└──────────────────────────────┘
```

### 1.3 技术栈

| 层 | 技术 |
| --- | --- |
| 前端 | Vue 3.4 + Vite 5 + Element Plus 2.7 + ECharts 5 + Pinia + vue-router |

## 3. 快速开始（5 分钟，免装数据库）

### 3.1 使用已构建产物

```bash
java -jar report-bi-platform-1.0.0.jar --spring.profiles.active=dev --server.port=18088
```

浏览器打开 <http://127.0.0.1:18088>，演示账号：

| 账号 | 密码 | 角色 |
| --- | --- | --- |
| `admin` | `123456` | ADMIN（管理员） |
| `analyst` | `123456` | ANALYST（分析师） |
| `viewer` | `123456` | VIEWER（查看者） |

> dev profile 数据在内存中，**进程重启即恢复初始状态**，只适合体验与联调。

### 3.2 从源码构建

```bash
# 1) 前端（产物输出到 backend/src/main/resources/static）
cd frontend && npm install && npm run build

# 2) 后端（含前端产物与依赖的 fat jar）
cd ../backend && mvn clean package -DskipTests
# 产物：backend/target/report-bi-platform-1.0.0.jar（约 54MB）

# 3) 运行（dev 免库）
java -Dfile.encoding=UTF-8 -jar target/report-bi-platform-1.0.0.jar --spring.profiles.active=dev --server.port=18088
```

构建注意：

- **必须先构建前端再打包后端**，否则 Jar 里没有 UI（访问 `/` 会 404）。
- 打包用 JDK 而非 JRE；`-DskipTests` 可跳过引擎单测（6 个用例）。

## 4. 生产部署

### 4.1 准备数据库

```sql
CREATE DATABASE rbi_platform DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE DATABASE rbi_testdb  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

CREATE USER 'rbi'@'%' IDENTIFIED BY '<强口令>';
GRANT ALL PRIVILEGES ON rbi_platform.* TO 'rbi'@'%';
GRANT ALL PRIVILEGES ON rbi_testdb.*  TO 'rbi'@'%';
FLUSH PRIVILEGES;
```

建表与种子数据由启动时的 `schema.sql` / `data.sql` 自动执行（幂等，`INSERT IGNORE`）。首次启动后可关闭：

```bash
SPRING_SQL_INIT_MODE=never
```

> 元数据库（报表/用户/权限）与业务库（demo_sales 或你的业务表）**建议分开**。业务库通过「数据源」功能接入，不需要写进配置文件。

### 4.2 目录规划

```bash
/opt/rbi/
├── report-bi-platform-1.0.0.jar
├── rbi.env            # 环境变量，权限 600
├── export/            # 调度导出落盘目录
└── logs/              # 应用日志（可交给 journald/文件采集）
```

### 4.3 环境变量文件

`/opt/rbi/rbi.env`（**权限 600**，不要提交到仓库）：

```bash
# ---- 数据库 ----
RBI_DB_URL=jdbc:mysql://10.0.0.10:3306/rbi_platform?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai
RBI_DB_USER=rbi
RBI_DB_PWD=<强口令>
RBI_TEST_URL=jdbc:mysql://10.0.0.10:3306/rbi_testdb?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai
RBI_TEST_USER=rbi
RBI_TEST_PWD=<强口令>

# ---- 安全（必填） ----
RBI_JWT_SECRET=<至少32字节随机串，务必自行生成>
RBI_ALLOWED_ORIGINS=https://bi.example.com
RBI_RESET_URL=https://bi.example.com/#/reset-password
SPRING_SQL_INIT_MODE=never

# ---- 邮件（找回密码、调度告警、报表推送） ----
RBI_MAIL_HOST=smtp.example.com
RBI_MAIL_PORT=465
RBI_MAIL_USER=bi@example.com
RBI_MAIL_PWD=<SMTP口令>
RBI_MAIL_TLS=true
RBI_MAIL_AUTH=true
RBI_MAIL_FROM=bi@example.com
RBI_ALERT_TO=ops@example.com

# ---- 调度（应用实例关闭，worker 开启） ----
RBI_SCHEDULE_ENABLED=false
RBI_EXPORT_DIR=/opt/rbi/export

# ---- 可选：API 数据集主机白名单 ----
RBI_API_DATASET_HOSTS=api.internal.example.com
```

生成密钥示例：`openssl rand -base64 48`

### 4.4 systemd（应用实例）

`/etc/systemd/system/rbi.service`：

```ini
[Unit]
Description=RBI Platform
After=network.target mysql.service

[Service]
Type=simple
User=rbi
WorkingDirectory=/opt/rbi
EnvironmentFile=/opt/rbi/rbi.env
ExecStart=/usr/bin/java -Dfile.encoding=UTF-8 -Xms512m -Xmx2g \
  -jar /opt/rbi/report-bi-platform-1.0.0.jar --server.port=8099
Restart=always
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

### 4.5 systemd（调度 worker，独立进程）

`/etc/systemd/system/rbi-worker.service`：

```ini
[Unit]
Description=RBI Scheduler Worker
After=network.target mysql.service

[Service]
Type=simple
User=rbi
WorkingDirectory=/opt/rbi
EnvironmentFile=/opt/rbi/rbi.env
Environment=RBI_SCHEDULE_ENABLED=true
ExecStart=/usr/bin/java -Dfile.encoding=UTF-8 -Xms256m -Xmx512m \
  -jar /opt/rbi/report-bi-platform-1.0.0.jar --spring.profiles.active=worker
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

> worker 用 `worker` profile：`spring.main.web-application-type=none` + `rbi.schedule.enabled=true`，不监听端口。
> **应用实例必须保持 `RBI_SCHEDULE_ENABLED=false`**，否则会与 worker 抢任务（有租约保护，但没必要）。

### 4.6 Nginx 反向代理

```nginx
server {
    listen 443 ssl http2;
    server_name bi.example.com;

    ssl_certificate     /etc/ssl/bi.crt;
    ssl_certificate_key /etc/ssl/bi.key;

    client_max_body_size 25m;   # 与 spring.servlet.multipart.max-file-size 对齐

    location / {
        proxy_pass http://127.0.0.1:8099;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;     # 大报表导出可能较慢
    }

    # 登录/找回密码接口额外限流
    location ~ ^/api/auth/(login|forgot)$ {
        limit_req zone=login burst=5 nodelay;
        proxy_pass http://127.0.0.1:8099;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

# http 段需要：limit_req_zone $binary_remote_addr zone=login:10m rate=10r/m;
```

### 4.7 启动与自检

```bash
systemctl daemon-reload
systemctl enable --now rbi rbi-worker
systemctl status rbi rbi-worker

curl -s http://127.0.0.1:8099/api/health          # {"status":"UP",...}
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8099/   # 200
```

### 4.8 升级与回滚

```bash
# 升级：先传临时文件，再停→换→起（不要直接覆盖运行中的 jar）
scp report-bi-platform-1.1.0.jar rbi@host:/opt/rbi/report-bi-platform-1.1.0.jar.tmp
ssh rbi@host '
  systemctl stop rbi rbi-worker
  mv /opt/rbi/report-bi-platform-1.1.0.jar.tmp /opt/rbi/report-bi-platform-1.1.0.jar
  ln -sfn /opt/rbi/report-bi-platform-1.1.0.jar /opt/rbi/current.jar
  systemctl start rbi rbi-worker
'
```

回滚：把软链指回旧版本并重启；数据库结构迁移是**向前兼容**的（只加列，不删列），可以直接回退代码。

### 5.2 认证与安全

| 配置项 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `jwt.secret` | `RBI_JWT_SECRET` | 仓库内置占位串 | **必须覆盖**，HS256 要求 ≥32 字节，否则启动失败 |
| `jwt.expiration` | `RBI_JWT_EXPIRATION` | `28800000`（8h） | 令牌与会话有效期 |
| `jwt.issuer` | `RBI_JWT_ISSUER` | `rbi-platform` | |
| `rbi.security.allowed-origins` | `RBI_ALLOWED_ORIGINS` | `localhost:5173,127.0.0.1:5173` | CORS 白名单，逗号分隔 |
| `rbi.security.reset-url` | `RBI_RESET_URL` | `http://127.0.0.1:18088/#/reset-password` | 找回密码链接的前端地址 |
| `rbi.security.reset-debug` | `RBI_RESET_DEBUG` | `false` | `true` 时找回密码接口直接返回 token（**仅联调**） |
| `rbi.security.pwd-expire-days` | `RBI_PWD_EXPIRE_DAYS` | `90` | 密码有效期（天），≤0 不过期 |

内置策略（不可配）：

- 密码强度：≥8 位，必须含字母+数字，不得与用户名相同；
- 登录锁定：同账号 5 次连续失败锁定 5 分钟（HTTP 429）；
- 令牌吊销：改密 / 重置 / 踢下线 / 退出全部 → 旧令牌立即 401。

## 6. 首次初始化与账号安全

### 6.1 首次登录

1. 用 `admin / 123456` 登录；
2. 系统提示"当前为初始/临时密码"，自动跳转「个人设置」→ 立即修改密码；
3. 修改成功后需重新登录（旧令牌立即失效）。

### 6.2 建账号

「平台管理 → 用户与角色 → 新建用户」：

- 用户名、姓名、状态；
- **初始密码由系统随机生成**，弹窗只显示一次，请转交用户；
- 新用户首次登录被强制改密；
- 给用户绑定角色（ADMIN / ANALYST / VIEWER，可自定义角色）。

用户列表操作：

| 操作 | 说明 |
| --- | --- |
| 分配角色 | 一个用户可多角色，取并集 |
| 编辑 | 改姓名/状态；**不能在此改口令** |
| 重置密码 | 生成随机临时口令，返回一次；同时踢掉该用户所有会话 |
| 踢下线 | 令牌版本 +1，所有设备立即失效（不改密码） |
| 删除 | 逻辑上直接删记录，不可恢复 |

### 6.3 绑定邮箱（找回密码前提）

用户记录必须有 `email` 才能收到重置链接。可在「用户与角色 → 编辑」里填写，或直接更新 `rbi_user.email`。

### 6.4 启用 MFA（推荐给管理员）

「个人设置 → 两步验证」：

1. 点「生成密钥」，得到 Base32 密钥与 otpauth 链接；
2. 在 Google/Microsoft Authenticator 中录入（扫码或手填）；
3. 输入当前 6 位动态码 → 「启用」。

之后登录流程变为两步：账号口令 → 动态码。关闭 MFA 也需要动态码。

### 6.5 会话管理

「个人设置 → 登录会话」列出所有设备（IP / UA / 最近活跃），可：

- 注销**单个**设备（单设备踢出）；
- 「退出所有会话」（令牌版本 +1，全部失效）。

### 6.6 找回密码

登录页「忘记密码？」→ 输入登录名 → 系统发送含一次性令牌的邮件（30 分钟有效）→ 点链接设置新密码。无论账号是否存在，提示一致（防枚举）。令牌使用一次即失效。

## 7. 功能操作指南

> 角色约定：**ADMIN** 全部；**ANALYST** 可建数据源/数据集/报表/图表并分析；**VIEWER** 只能看报表、图表、填报与分析结果。

### 7.1 数据源

「数据接入 → 数据源」→「新建数据源」：

| 字段 | 说明 |
| --- | --- |
| 名称 | 展示用 |
| 类型 | mysql/oracle/sqlserver/postgresql/dm/kingbase/gaussdb |
| 驱动类 | 可从「驱动列表」选择，需对应 JDBC 驱动在 classpath |
| JDBC URL | 如 `jdbc:mysql://host:3306/db?...` |
| 用户名/口令 | 口令加密存储，接口不回传 |

「测试连接」只有 **ADMIN** 可用（它会发起服务器侧外联，属高风险操作）。

> 国产库（达梦/金仓/GaussDB）需把厂商驱动 jar 加进 `pom.xml` 或 `-cp`。

### 7.2 数据集

「数据接入 → 数据集」→「新建数据集」。支持三类：

**① SQL 数据集**（最常用）

```sql
SELECT order_date, region, province, category, amount
FROM demo_sales
WHERE 1=1 ${region_filter} ${date_filter} ${row_filter}
```

占位符规则：

| 占位符 | 来源 | 生成内容 |
| --- | --- | --- |
| `${param}` | 查询参数 | 按类型安全转义的字符串字面量 |
| `${region_filter}` / `${xxx_filter}` | 参数名以 `_filter` 结尾 | ` AND 列 = '值' `（列名做标识符白名单校验） |
| `${date_filter}` | `startDate` 参数（`yyyy-MM-dd`） | ` AND order_date >= '...'` |
| `${row_filter}` | **行级数据权限** | ` AND 列 IN (...) ` 或表达式；**必须保留，否则配了行权限会 403** |

其他行为：单次查询上限 5000 行（未写 `LIMIT` 时自动追加）；结果按"数据集 + 数据源 + 用户 + 参数"缓存，缓存时长由「缓存秒数」决定。

**② API 数据集**

```json
{
  "url": "https://api.example.com/sales?page=${page}&size=${size}",
  "method": "GET",
  "headers": { "X-Token": "xxx" },
  "dataPath": "data.rows",
  "paging": { "start": 1, "size": 100, "maxPages": 20 }
}
```

- 目标主机必须在 `RBI_API_DATASET_HOSTS` 白名单内（留空则禁用）；
- `${page}`/`${size}`/`${offset}` 在分页模式下自动替换；
- `dataPath` 用点号取嵌套节点，识别 `{"data":[...]}` 结构。

**③ 可视化 / 文件数据集**：数据预置在 `config_json.data` 中。

### 7.3 参数

「报表与分析 → 参数与查询」：定义编码、类型（text/select/multiselect/date/tree）、选项、默认值、联动父参数。报表设计器与数据集查询都可引用；「参数联动」页可实测父子联动（选中大区后省份自动过滤）。

### 7.4 报表设计器

「报表 → 设计器」。

**单元格类型**

| 类型 | 用途 | 关键属性 |
| --- | --- | --- |
| `text` | 标题、表头、固定文字 | 样式（加粗/底色/对齐/字号/跨列） |
| `dataset` | 绑定数据集字段 | `field`、`expand`（v 纵向 / h 横向 / none）、`parent`（父格） |
| `formula` | 公式聚合 | `value`，如 `SUM(amount)`、`A1+B1`、`IF(...)` |

**扩展引擎**：父格先展开，父格每个取值形成一个分组上下文，子格在上下文内继续展开，并把父格的行区间"撑开"（父格值纵向合并显示）。公式格在所在分组上下文内聚合。

**支持的公式**：`SUM/AVG/COUNT/MAX/MIN/IF/CONCAT/ROUND`、四则运算、单元格引用（`A1+B1`）。不使用脚本引擎。

**分页与页脚**（布局 JSON 字段）

| 字段 | 说明 |
| --- | --- |
| `headerRows` | 每页重复的表头行数 |
| `pageSize` | 每页数据行数（0 = 按纸张自动分页） |
| `breakOn` | 按该字段分组换页（值变化即起新页） |
| `footerText` | 页脚文字，支持 `{page}` / `{pages}` / `{date}` |
| `pageSizeName` | `A4` / `A3` / `LETTER`（横向） |

**条件样式**：单元格 `style.rules` 支持

```json
{ "rules": [ { "when": ">15000", "bg": "#FFF2CC", "color": "#C00000", "bold": true } ] }
```

运算符：`>` `>=` `<` `<=` `==` `!=` `contains:`；PDF 与 Excel 同时生效。

**预览与保存**：设计器右上有「实时预览」（直接渲染未保存布局）与「保存」（生成新版本，可回滚）。

### 7.5 报表管理

列表可「渲染预览」「导出 Excel」「导出 PDF」「设计」「删除」。导出带水印（导出人 + 时间 + 仅限内部使用），PDF 为 A4 横向。

### 7.6 图表与仪表板

「可视化 → 图表设计」：选数据集 → 配维度/度量/聚合 → 预览；「仪表板大屏」自由拖拽布局，深色背景适配大屏。

### 7.7 数据填报

「数据填报」：按表单定义渲染输入项，前端做必填/类型/范围/正则校验，提交后后端**再次校验**并用 `PreparedStatement` 事务批量写库。单次最多 1000 行。表单定义（`table_name` + `fields_json`）决定目标表与字段。

### 7.8 自助分析

拖维度（行/列）、度量（字段 + 聚合）、过滤、排序，支持占比/排名/累计。

- 引擎默认 `auto`：优先把分组聚合**下推到数据库**，失败回退内存聚合，响应里 `engine` 字段标明实际引擎；
- 可显式指定 `"engine": "sql"` 或 `"memory"`；
- 「查看 SQL」给出可执行的等价 SQL（基于数据集真实 SQL，含行级权限）。

### 7.9 指标

定义原子指标（`SUM(amount)`）与派生指标（`TOTAL_SALES / COUNT(order_date)`），维护口径与血缘（依赖表/字段/其他指标）。

### 7.10 权限配置（三层）

**资源级**：「平台管理 → 目录与权限」

| 概念 | 说明 |
| --- | --- |
| 资源类型 | `directory`（目录）/ `report`（报表） |
| 权限 | `view`（可见）/ `edit`（可编辑）；`export` 为预留值，当前不做强制校验 |
| 生效规则 | 某资源**一旦有记录**，只有被授权角色可见；**无记录视为公开**；ADMIN 不受限 |

**行级**（同页面「数据权限」区）

| 字段 | 说明 |
| --- | --- |
| 角色 / 数据集 | 作用范围 |
| 模式 `values` | 列 + 逗号分隔的允许值 → `列 IN ('a','b')` |
| 模式 `expr` | 表达式，如 `amount < 10000 AND region = '华北'` |

表达式能力与限制：

- 支持比较、`AND/OR/NOT`、`IN`、括号、中文字面量；
- 支持函数白名单：`lower/upper/coalesce/abs/round/year/month/day/length/trim`；
- 支持上下文变量：`${deptId}`、`${userId}`、`${deptTree}`（当前用户部门子树 ID 列表，实现部门树继承）；
- **禁止**子查询、DML/DDL 关键字、注释、堆叠语句、`sleep()` 等；保存时即校验；
- 若某数据集配了行权限但 SQL 没有 `${row_filter}` → 查询直接 **403**（fail-closed）。

**列级**（同页面「列级权限 / 脱敏」）

| 策略 | 效果 |
| --- | --- |
| `hidden` | 结果中不返回该列 |
| `mask_all` | `******` |
| `mask_phone` | `138****1234` |
| `mask_idcard` | `110***********1234` |
| `mask_email` | `a***@example.com` |
| `mask_name` | `张*` |

同一列命中多条取最严格；脱敏在数据出口统一生效，报表/图表/分析/导出看到的是同一份受限数据；被隐藏的列**不允许**用于分析的分组或聚合（否则可反推原值）。

### 7.11 定时调度

「平台管理 → 定时调度」→「新建任务」：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | |
| 关联报表 | 报表 ID |
| cron | Spring 6 段式，如 `0 0 9 * * ?`（每天 09:00） |
| 类型 | `refresh` 刷缓存 / `export` 导 Excel 落盘 / `email` 推送附件 |
| 接收人 | 邮箱，逗号分隔（email 类型） |
| 状态 | 启用/停用 |
| 最大重试 | 默认 3 |

- 「立即执行」不影响 cron 的下次时间；
- 失败按 `1,5,15` 分钟退避重试，用尽后给 `RBI_ALERT_TO` 发告警并回到正常周期；
- 任务列表可见 `lastRunTime` / `nextRunTime` / `lastError` / 重试计数；
- 多实例安全：领取任务时用 `locked_until` 租约（5 分钟）；
- **必须由 worker 进程执行**（应用实例默认不跑调度）。

### 7.12 操作日志

「平台管理 → 操作日志」：记录所有写操作的操作人、模块、接口、结果、耗时、错误摘要、IP。支持按用户/模块筛选、导出 CSV（带导出人水印）。最多展示最近 500 条。

### 7.13 部署运维页

「部署运维」：JVM 内存/CPU、节点信息、运行时长（`/api/admin/health`），以及部署方式说明。健康检查对外用公开的 `/api/health`。

## 8. 关键机制说明

### 8.1 登录与会话

```
POST /api/auth/login  →  {token, userId, username, roles, mustChangePwd, pwdExpired, sessionId, expiresIn}
```

- 令牌是 JWT（HS256），携带 `uid / roles / ver / dept / jti`；
- 每次请求拦截器会校验：签名 → issuer → 过期 → **令牌版本** → **会话 jti 有效且未注销**；
- 所有 `/api/**` 都要求令牌，例外：`/api/auth/login`、`/api/auth/login/mfa`、`/api/auth/forgot`、`/api/auth/reset`、`/api/auth/oidc/**`、`/api/health`。

### 8.2 权限判定顺序

```
1) 是否登录？          否 → 401
2) /api/admin/** ?     是且非 ADMIN → 403
3) 方法/类上有 @RequireRole ? 不满足 → 403
4) 访问报表/数据集时：资源级 → 行级（注入 SQL） → 列级（出口脱敏）
```

### 8.3 导出与水印

| 格式 | 水印位置 |
| --- | --- |
| CSV | 首行注释 `# 导出人 X · 时间 · 仅限内部使用` |
| Excel | 页眉居中 |
| PDF | 页脚（与自定义页脚文字拼接） |

定时任务导出的水印为 `导出人 system(定时任务)`。

### 8.4 缓存

数据集查询缓存为进程内 Map（每个实例独立），键 = 数据集 + 数据源 + 用户 + 参数；上限 5000 条，超限整体清空。改数据集会主动清该数据集缓存。多实例部署时缓存不共享，属预期行为。

### 8.5 数据库表

| 表 | 用途 |
| --- | --- |
| `rbi_user` / `rbi_role` / `rbi_user_role` | 账号、角色、关联（含 `token_version`/`mfa_*`/`pwd_*`/`email`） |
| `rbi_user_session` | 登录会话（jti/IP/UA/最后活跃/吊销） |
| `rbi_reset_token` | 找回密码一次性令牌 |
| `rbi_dept` | 部门树（行级 `${deptTree}` 依赖） |
| `rbi_directory` | 资源目录树 |
| `rbi_permission` | 资源级权限 |
| `rbi_data_scope` | 行级权限（`values` / `expr`） |
| `rbi_column_policy` | 列级权限与脱敏 |
| `rbi_datasource` / `rbi_dataset` | 数据源、数据集 |
| `rbi_report` / `rbi_report_version` | 报表模板、版本 |
| `rbi_param` | 参数定义 |
| `rbi_chart` / `rbi_dashboard` | 图表、仪表板 |
| `rbi_form` / `rbi_analysis` / `rbi_metric` | 填报、分析配置、指标 |
| `rbi_schedule` | 调度任务（含租约、重试、错误） |
| `rbi_op_log` | 审计日志 |
| `demo_sales`（业务库） | 演示销售明细，首次启动自动灌入 |

## 9. 运维任务

### 9.1 备份与恢复

```bash
# 备份（元数据 + 业务库）
mysqldump -uroot -p --single-transaction --routines \
  rbi_platform > /backup/rbi_platform_$(date +%F).sql
mysqldump -uroot -p --single-transaction rbi_testdb > /backup/rbi_testdb_$(date +%F).sql

# 恢复
mysql -uroot -p rbi_platform < /backup/rbi_platform_2026-11-17.sql
```

建议：每日全量 + binlog 增量；**每季度做一次恢复演练**（没演练过的备份等于没有）。

### 9.2 日志

- 应用日志走 stdout（systemd 收集到 journald）：`journalctl -u rbi -f`；
- 审计日志在库表 `rbi_op_log`，可通过界面筛选或导出 CSV；
- 日志级别：默认 INFO，排障时临时加 `--logging.level.com.rbi=DEBUG`。

### 9.3 健康检查与监控

| 端点 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/health` | 公开 | 存活探针（status / uptime / jvm） |
| `GET /api/admin/health` | ADMIN | JVM 内存、CPU 核数、运行时长 |

建议监控项：`/api/health` 可用性、JVM 堆使用率、MySQL 连接数、登录 401/429 速率、调度任务 `last_error`。

### 9.4 扩缩容与多节点

已具备：会话在库、令牌版本在库、调度租约在库 → 应用可水平扩展。

需要注意（尚未共享化）：

| 项 | 影响 | 规避 |
| --- | --- | --- |
| 登录失败计数 | 内存实现，按节点各自计数 | 用 Nginx 对 `/api/auth/login` 限流兜底 |
| OIDC state | 内存实现，回调需落在同一节点 | 粘性会话，或改用 Redis（后续） |
| 数据集缓存 | 每实例独立 | 属预期，接受缓存不一致时间 |
| 调度 | 由 worker 独占 | 只部署一个 worker（多 worker 有租约兜底） |

### 9.5 升级注意

1. 先备份；
2. 前端产物必须在打包前构建（否则 Jar 内 UI 为旧版）；
3. 停机窗口内 `stop → 换 jar → start`，不要覆盖运行中的文件；
4. 结构迁移只加列，回滚安全；
5. 升级后跑一遍第 12 章的冒烟脚本。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 启动即退出，日志 `jwt.secret 长度不足` | `RBI_JWT_SECRET` 未设或太短 | 设置 ≥32 字节的密钥 |
| 启动报 `Port 8088 was already in use` | 端口占用 | `--server.port=8099` 或杀掉占用进程 |
| 访问 `/` 404 | 前端未构建就打包 | 先 `npm run build` 再 `mvn package` |
| 登录返回 429 | 同账号 5 次失败被锁 5 分钟 | 等待或换账号；检查是否被撞库 |
| 所有接口 401 | 令牌过期 / 被踢 / 改密后旧令牌 | 重新登录 |
| 打开报表 403「无权查看该资源」 | 资源级权限未授权 | 到「目录与权限」授权，或确认无记录（无记录=公开） |
| 查询报 403「未定义 ${row_filter}」 | 配了行权限但数据集 SQL 缺占位符 | 在数据集 SQL 末尾补 `${row_filter}` |
| 查询报「只允许只读查询」 | `/api/sql/execute` 传了写语句/多语句 | 该接口仅支持单条 SELECT/WITH |
| 中文乱码 | 客户端未按 UTF-8 解析 | 检查反代是否透传 charset（服务端已强制 `charset=UTF-8`） |
| 找回密码收不到邮件 | SMTP 未配 / 用户无 email | 配 `RBI_MAIL_*`，给用户补 email；查应用日志 `[邮件]` |
| 登录返回 503「目录服务暂不可用」 | 启用了 LDAP 但目录连不上 | 检查 `RBI_LDAP_URL`/网络；或先用本地账号 |
| 调度任务一直不执行 | 应用实例 `RBI_SCHEDULE_ENABLED=false` 且未部署 worker | 启动 worker 进程；或临时置 true 排障 |
| 调度报「任务正在执行中」 | 租约未释放（进程被杀） | 等 5 分钟租约过期，或把 `locked_until` 置空 |
| 调度 `lastError` 指向报表不存在 | 任务关联了已删除报表 | 改任务关联或删除任务 |
| 导出 PDF 中文变方框 | 缺少 CJK 字体资源 | 确认 `openpdf-fonts-extra` 在依赖里；查日志「回退 Helvetica」 |
| 导出 Excel 500，日志 `Style does not belong to this workbook` | 旧版本样式缓存 bug（v1.4 已修） | 升级到当前版本 |
| 分析结果与手算不一致 | 用错了引擎或过滤条件 | 看响应 `engine` 字段；用「查看 SQL」核对 |
| 列权限未生效 | 用户是 ADMIN（不受限）或有更宽松策略 | 换非管理员账号验证 |
| 登录后立刻被踢 | 管理员执行了「踢下线」或改密 | 重新登录 |

## 11. 安全加固与上线检查单

### 11.1 必做

- [ ] `RBI_JWT_SECRET` ≥32 字节随机串（不要用仓库默认值）
- [ ] `RBI_ALLOWED_ORIGINS` 为真实域名，删除 localhost
- [ ] 首次初始化后 `SPRING_SQL_INIT_MODE=never`
- [ ] MySQL 使用独立账号（非 root），元数据与业务库分离
- [ ] Nginx 终结 TLS，后端只监听内网

### 13.2 响应格式与错误码

```json
{ "code": 0, "msg": "success", "data": {...}, "timestamp": 1700000000000 }
```

HTTP 状态与 `code` 一致：

| 码 | 含义 |
| --- | --- |
| 400 | 参数错误 / 校验失败 / 表达式非法 |
| 401 | 未登录 / 令牌过期 / 会话失效 / 动态码错误 |
| 403 | 无权限 / 账号禁用 / 资源未授权 / 行权限 fail-closed |
| 404 | 资源不存在 |
| 409 | 调度任务正在执行 |
| 429 | 登录失败次数过多（锁定 5 分钟） |
| 500 | 服务器内部错误（响应含 `traceId`，堆栈仅在服务端日志） |
| 503 | 目录服务（LDAP）不可用 |
